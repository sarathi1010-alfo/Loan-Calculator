# Indexing Failure Debugger

When Google Search Console flags issues, use this guide to diagnose and fix them within our Next.js architecture.

### 1. "Crawled - currently not indexed"
- **Cause:** Googlebot read the page but decided it wasn't high-quality enough or unique enough to put in the index. (Thin content).
- **Diagnosis:** Compare the page to a sibling page. Are they 95% identical?
- **Fix:** Enhance the programmatic generation script to output more unique semantic blocks, dynamic FAQs, or specialized data tables.

### 2. "Discovered - currently not indexed"
- **Cause:** Google knows the URL exists but the server was overloaded, so it postponed the crawl.
- **Diagnosis:** Check Vercel TTFB and GSC Crawl Stats response time.
- **Fix:** Switch the route from SSR to ISR (`revalidate = 86400`) so Googlebot hits Edge Cache instead of triggering serverless functions.

### 3. "Duplicate, Google chose different canonical than user"
- **Cause:** The page is too similar to another tool, and Google consolidated them.
- **Diagnosis:** Check the URL Google *actually* indexed instead.
- **Fix:** If the consolidation is wrong, differentiate the page titles, H1s, and text deeper. If it's correct, implement a 301 redirect or merge the pages.

### 4. "Page with redirect"
- **Cause:** Normal behavior if we pruned a page. Error if it's a live tool.
- **Diagnosis:** Check if trailing slashes are causing a redirect loop (`/tool` -> `/tool/`).
- **Fix:** Enforce strict trailing slash policy in `next.config.js`.

### 5. "Blocked by robots.txt"
- **Cause:** Misconfigured robots.txt blocking a valid path.
- **Diagnosis:** Check if the URL contains parameters blocked by `Disallow: /*?*`.
- **Fix:** Update `app/robots.ts` or `public/robots.txt`.

### 6. "Server error (5xx)"
- **Cause:** The Vercel Serverless Function timed out or crashed during Googlebot's request.
- **Diagnosis:** Check Vercel Error Logs for the specific path. Usually caused by a failing API or unhandled null data in the page component.
- **Fix:** Wrap data fetching in `try/catch`, return `notFound()` on null, and fix the underlying crash.
