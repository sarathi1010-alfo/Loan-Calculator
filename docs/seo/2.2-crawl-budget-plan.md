# Crawl Budget Optimization Plan

For a 1,000+ page micro-tool ecosystem, maximizing Googlebot's efficiency is critical.

## 1. Prioritized Next.js Optimizations

1. **ISR Edge Caching:** Serve pre-rendered HTML from the Vercel Edge. Prevents server compute time from eating crawl budget.
2. **Remove Non-Essential JS for Bots:** Delay heavy third-party scripts (analytics, ads) until user interaction (`next/script` `strategy="lazyOnload"`).
3. **Flat Folder Structure:** Ensure all tools are at `/[cluster]/[tool]`. Deep nesting wastes crawl budget.
4. **Internal Link Pruning:** Ensure pagination and filter links use `rel="nofollow"` if they generate duplicate parameter URLs.
5. **XML Sitemap Segmentation:** Split sitemaps by cluster (max 10k URLs per map) so Google can process them faster.

## 2. Robots.txt Template

```text
User-agent: *
Allow: /

# Prevent crawl budget waste on APIs and builds
Disallow: /api/
Disallow: /_next/
Disallow: /admin/
Disallow: /private/

# Prevent parameter bloat
Disallow: /*?*
Allow: /*?page=*

Sitemap: https://loancalculatorhub.com/sitemap.xml
```

## 3. Server Performance Checklist (Vercel)

- [ ] Ensure `next/image` is only used for actual photos; use standard `<img>` or CSS for simple icons to avoid Vercel Image Optimization compute overhead.
- [ ] Check Vercel logs for 5xx errors; 5xx errors immediately tell Googlebot to slow down crawling.
- [ ] Use `React.Suspense` for any dynamic data fetching so the static shell streams immediately.

## 4. Monitoring Plan (GSC)

Watch the **Crawl Stats** report weekly (Settings > Crawl Stats):

- **Total crawl requests:** Should trend upwards.
- **Average response time:** Must stay under 1,000ms.
- **By purpose:** Watch "Refresh" vs "Discovery". If Discovery is low, we have an internal linking or sitemap issue.
