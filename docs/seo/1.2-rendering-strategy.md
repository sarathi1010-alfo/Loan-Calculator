# Rendering Strategy Selector

## Context

When building Next.js App Router applications for Programmatic SEO, selecting the correct rendering strategy ensures rapid Googlebot crawling, high performance, and correct indexing.

## Selection Matrix

| Tool Type                    | Example          | Recommended Strategy             | Rationale                                                                                                                              |
| :--------------------------- | :--------------- | :------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------- |
| **Real-time unit converter** | kg to lbs        | **SSG** (Static Site Generation) | Pure deterministic function based solely on input; no backend dependencies. High cache hit rate.                                       |
| **PDF thumbnail generator**  | File upload tool | **CSR** (Client-Side Rendering)  | Heavy lifting occurs on the user's browser; output depends completely on user upload. Shell is SSG.                                    |
| **Static "Best of" article** | "Best PDF tools" | **SSG**                          | Content is highly static, updates rarely. Highest performance needed for informational queries.                                        |
| **Color palette generator**  | Hex to RGB       | **SSG** / **ISR**                | Infinite permutations based on search intent, but outputs are deterministic. Pre-generate top 10k permutations (SSG), fallback to ISR. |
| **Resume template showcase** | Resume builder   | **ISR**                          | Content updates moderately often (new templates added). Fast TFB required, but content must remain fresh.                              |
| **Educational Guide**        | "What is CMYK"   | **SSG**                          | Completely static informational content.                                                                                               |

## Next.js App Router Implementation Patterns

### 1. SSG (Static Site Generation)

Used for purely static pages or deterministic tools with finite search permutations.

```tsx
// app/guides/[slug]/page.tsx
export async function generateStaticParams() {
  const guides = await getGuides();
  return guides.map((guide) => ({ slug: guide.slug }));
}

export default async function GuidePage({
  params,
}: {
  params: { slug: string };
}) {
  const data = await getGuideData(params.slug);
  return <div>{data.title}</div>;
}
```

### 2. ISR (Incremental Static Regeneration)

Used for programmatic tool pages (e.g., loan calculators) where permutations are too vast to pre-build everything.

```tsx
// app/loan/[slug]/page.tsx
// Next.js 14+ specific revalidation approach
export const revalidate = 604800; // Revalidate weekly (in seconds)
export const dynamicParams = true; // Allow ISR on-demand for unknown paths

export async function generateStaticParams() {
  // Pre-build the top 100 highest-traffic routes
  const topSlugs = await getTopPerformers();
  return topSlugs.map((s) => ({ slug: s }));
}

export default async function ToolPage({
  params,
}: {
  params: { slug: string };
}) {
  const toolData = await fetchToolData(params.slug); // Cached fetch
  return <Calculator toolData={toolData} />;
}
```

### 3. CSR / Hybrid (Client-Side Rendering within a Static Shell)

Used when the tool requires user input (like a file upload). The page SEO shell is SSG, but the heavy logic is an isolated Client Component.

```tsx
// app/pdf-compressor/page.tsx
import { Metadata } from "next";
import dynamic from "next/dynamic";

export const metadata: Metadata = {
  title: "PDF Compressor",
  description: "...",
};

// Isolate the heavy client logic, prevent SSR hydration errors
const PdfCompressorClient = dynamic(
  () => import("@/components/PdfCompressorClient"),
  { ssr: false },
);

export default function Page() {
  return (
    <main>
      <h1>Compress PDF</h1>
      <PdfCompressorClient />
    </main>
  );
}
```
