# Content Pruning Decision Framework

With programmatic SEO, index bloat is the biggest enemy. If we generate 5,000 tool combinations, 2,000 might never get traffic. We must prune them to save crawl budget.

## Pruning Criteria Matrix

| Age of Page | Impressions/Mo | Clicks/Mo | Action | Rationale |
| :--- | :--- | :--- | :--- | :--- |
| < 3 Months | Any | Any | **KEEP** | Still in the sandbox; Google is testing it. |
| > 6 Months | < 50 | 0 | **PRUNE** (410 Gone) | Zero demand. It is wasting crawl budget and diluting domain quality. Remove from `seo-pages.json`. |
| > 6 Months | > 500 | < 2 | **CONSOLIDATE** | Demand exists, but we can't rank. 301 Redirect this specific variation up to the broader Hub page. |
| > 6 Months | > 1000 | > 50 | **OPTIMIZE** | Strong signals. Add custom, manual paragraphs to this specific page to boost EEAT. |

## Pruning SOP (Standard Operating Procedure)

1. **Identify Candidates:** Export GSC URL data for the last 6 months. Filter for Impressions < 50.
2. **Remove from Ontology:** Update the generation constraints in `scripts/generate-seo-entities.ts` to exclude these specific permutations (e.g., "Stop generating 1-year home loans").
3. **Regenerate System:** Run `npm run generate-entities`.
4. **Implement 410 or 301:** Update Next.js `next.config.js` or `middleware.ts` to return a 410 (Gone) for pruned URLs, or a 301 to the Hub.
5. **Update Sitemaps:** Ensure the sitemap index generator naturally drops the removed URLs. Googlebot will recrawl, see the 410/301, and remove them from the index.
